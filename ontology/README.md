# locx ontology

`locx.owl.ttl` is the OWL 2 ontology of the locx knowledge graph. It is **hand-maintained and is the source of
truth**: the RDF builders, SHACL shapes, verdict rules and demo read their classes, properties and values from it
(`locx/ontology.py`). Edit it in Protégé, keeping `catalog-v001.xml` next to it, then run `make ontology` (loads it
into graph `urn:locx:graph:ontology`) and `make check-ontology`. If you rename or remove a term the code uses, the
build stops and names the term. The whole data model is in [`docs/DATA_MODEL.md`](../docs/DATA_MODEL.md).

| File | What |
|---|---|
| `locx.owl.ttl` | the locx ontology (11 commented sections). Imports the official GO, ECO, RO and UniProt core ontologies |
| `catalog-v001.xml` | points Protégé to the local copies of the exact GO / ECO / RO releases in `data/raw/obo/`. Without them (e.g. on a laptop), Protégé downloads the current releases from the OBO PURLs |
| `sample_TFEB.ttl` | everything the graph holds about one protein (TFEB), generated by `make check-ontology`, importing the ontology: UniProt names and location, assertions with support and verdicts, claims with their evidence sentences and abstracts, GOA rows with evidence and contexts, papers with journals, citation counts, authors and institutions, GO terms with their ancestors, the activities |

## Open in Protégé

1. **File → Open** `sample_TFEB.ttl`, or `locx.owl.ttl` for just the vocabulary.
2. **Entities → Classes**: our classes (LocalizationStatement with Claim and CuratedAnnotation, Assertion,
   Authorship, Support, AuthorGroup, Verdict, the value lists), the outside classes we use (up:Protein, fabio:Journal,
   foaf:Person, prov:Activity, oa:SpecificResource, …) and the imported GO, ECO and RO.
3. **Individuals**: the values (locx:Hedged, locx:MethodNotStated, …) and, in the sample, assertions, claims,
   location individuals (typed with their GO class), GOA evidence individuals (typed with their ECO class), papers,
   persons.
4. **Reasoner → HermiT → Start reasoner** checks consistency and shows inferred types (e.g. a nucleoplasm location
   is also a cellular component).

Turn on *View → Render by label* if names show as IRIs.

## Modelling choices

- **One pattern for every value list**: an OWL class with exactly its individuals (`owl:oneOf`, all different); each
  value has `rdfs:label`, `rdfs:comment` and `locx:token` (the string the pipeline uses). No SKOS.
- **No punning**: a statement's location is an individual typed with its GO class (`…/location a obo:GO_0005634`,
  the GO-CAM pattern), and a GOA row's evidence an individual typed with its ECO class. `locx:location` and
  `locx:evidence` have real ranges (`obo:GO_0005575`, `obo:ECO_0000000`). RO relations (`locx:relation`) and
  the relation and term of a context part are annotation properties, because their values are RO properties or classes of
  ontologies we do not load. Every claim states *located in*: `locx:statesRelation obo:RO_0001025` on `locx:Claim`.
- **Outside ontologies first**: UniProt core, PROV-O, FaBiO/FRBR/PRISM/C4O, W3C Web Annotation, FOAF, Dublin Core.
  These terms are declared (type + `rdfs:isDefinedBy`), never redefined; an outside class gets only a
  `locx:usageNote`.
- **GO evidence categories** (the GO guide's seven) are defined over ECO classes (`locx:ecoRoot`,
  `locx:ecoExcludedRoot`) with our strength rank (`locx:evidenceRank`).
- **Our statements about GO terms** (too generic, non-human compartment roots) are in section 10, not in GO.
- **Contexts**: `locx:Context` is what a statement holds under, with two subclasses. A `locx:GOAContext` is one
  alternative of a GOA annotation extension, made of `locx:ContextPart`s (an RO relation and a term, e.g. *part of*
  CL:0000540 neuron). A `locx:FreeTextContext` is a condition or cell type as the paper words it (`locx:contextText`,
  `locx:contextKind`). Both hang on `locx:hasContext`, so a free-text context can later get the same parts once it
  is grounded.
- **ORCID** (`locx:orcid`) is inverse functional, so the reasoner merges OpenAlex authors that share an ORCID.

## Checks (`make check-ontology` → `reports/ontology.json`)

- coverage: every class and predicate in our data graphs is declared here;
- outside IDs: the GO, ECO, RO and NCBITaxon IDs written here exist in their sources;
- HermiT on this ontology + ECO + UniProt core + GO's cellular-component module: consistent, no unsatisfiable
  classes. UniProt core is read without its web imports (FALDO, SKOS, FOAF), and its 5 axioms with `xsd:date`,
  `xsd:gYear` or `xsd:gYearMonth` are widened to `rdfs:Literal` for HermiT, which supports only the OWL 2 datatypes. It is not run
  on all of GO (does not finish in 30 min) or with RO (does not finish in 5 min; RO is used only as annotation
  values);
- the Protégé sample is checked triple by triple against domains, ranges, functional properties and disjoint
  classes.
